There are disconnected connectors.

Diagnostics

Compare the number of registrations with active sessions; check the network, certificate expiration, and SDK buffer.

  1. Open the related dashboard, retain the time interval and select the node or service named in the alert.
  2. Check collection freshness, replica availability and recent errors. Compare them with configuration changes.
  3. Run on the node docker compose -f /var/lib/psim-platform/config/<node>/compose.json ps.
  4. For a container, check docker compose -f /var/lib/psim-platform/config/<node>/compose.json logs --tail=100 <service>; for a native service, use systemctl status psim-<service>.

Recovery

Restore connectivity and verify buffered delivery, final command outcomes and the absence of new losses.

Verification

The component check succeeds, metric series update and the alert becomes resolved after a full evaluation window. Check dependent queues and a functional operation.

If recovery is incomplete, retain diagnostics without secrets and send them to the subsystem owner. Do not disable the alert instead of fixing its cause.
