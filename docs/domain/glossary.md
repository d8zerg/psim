# Глоссарий

Версия 0.1 · Шаг плана 0.2 · Статус: черновик

Единый язык проекта. Термины используются одинаково в документации, коде, контрактах и интерфейсе. В коде применяется английское имя из столбца «Код».

## Общие правила

- Все идентификаторы сущностей - UUIDv7, если явно не указано детерминированное построение (см. [aggregates.md](aggregates.md), раздел 0).
- Любая сущность и любое сообщение содержат `tenant_id`.
- Время хранится в UTC с точностью до микросекунд. Различаются **время возникновения** (`occurred_at`, по часам источника) и **время приёма** (`received_at`, по часам платформы).

## Термины

| Термин | Код | Контекст | Определение |
|---|---|---|---|
| Тенант | `Tenant` | Platform | Изолированная организация-владелец данных. В MVP один, но присутствует во всех ключах |
| Локация | `Location` | Catalog | Узел иерархии защищаемого объекта: площадка, здание, этаж или зона |
| Площадка | `Site` | Catalog | Корневая локация: территориально обособленный объект (завод, кампус, станция) |
| Здание | `Building` | Catalog | Локация внутри площадки |
| Этаж | `Floor` | Catalog | Локация внутри здания; может иметь поэтажный план |
| Зона | `Zone` | Catalog | Наименьшая локация, к которой привязываются устройства и правила. Может находиться на этаже, в здании или прямо на площадке (наружные и периметральные зоны) |
| Поэтажный план | `FloorPlan` | Catalog | Изображение этажа с системой координат для размещения устройств |
| Тип устройства | `DeviceType` | Catalog | Класс устройств с набором источников и возможностей (датчик движения, дверь СКУД, камера) |
| Устройство | `Device` | Catalog | Физическое или логическое оборудование, привязанное к зоне и обслуживаемое одним коннектором |
| Источник | `Source` | Catalog | Канал событий устройства: шлейф, вход, детектор видеоаналитики. У устройства один или несколько источников. Ключ партиционирования сырых событий |
| Возможность | `Capability` | Catalog | Поддерживаемая устройством команда или режим (`lock`, `unlock`, `arm`, `ptz.preset`) |
| Коннектор | `Connector` | Catalog / Integration | Программный адаптер внешней системы к платформе, зарегистрированный в каталоге и имеющий учётные данные mTLS |
| Сессия коннектора | `ConnectorSession` | Integration | Время жизни одного подключения коннектора к шлюзу |
| Сырое событие | `RawEvent` | Integration | Событие в виде, переданном коннектором: идентификатор источника, порядковый номер, исходный код события, атрибуты |
| Порядковый номер источника | `source_seq` | Integration | Монотонно растущий номер события у источника. Используется для дедупликации и сквозной сверки |
| Правило отображения | `MappingRule` | Event Processing | Декларативное правило перевода сырого события в тип таксономии и критичность |
| Событие | `Event` | Event Processing | Нормализованное событие: тип таксономии, критичность, площадка, зона, устройство, источник |
| Значимое событие | `SignificantEvent` | Event Processing | Событие с критичностью не ниже порога или связанное с сигналом. Сохраняется в Event History |
| Таксономия | `Taxonomy` | Event Processing | Иерархический справочник типов событий, см. [event-taxonomy.md](event-taxonomy.md) |
| Критичность | `Severity` | Event Processing | Важность отдельного события: `info`, `low`, `medium`, `high`, `critical` |
| Правило корреляции | `CorrelationRule` | Event Processing | Декларативное правило, порождающее сигнал из одного или нескольких событий: условие, окно, последовательность, порог или отсутствие события |
| Набор правил | `RuleSet` | Event Processing | Версионированная совокупность активных правил тенанта, применяемая атомарно |
| Ключ корреляции | `correlation_key` | Event Processing | Ключ, по которому правило накапливает состояние (например, зона). Ключ партиционирования сигналов |
| Окно | `Window` | Event Processing | Интервал event time, в котором правило сопоставляет события |
| Водяной знак | `Watermark` | Event Processing | Оценка момента event time, до которого все события считаются полученными |
| Сигнал | `Signal` | Event Processing | Результат срабатывания правила: признак ситуации, требующей внимания. Содержит тип инцидента, приоритет, ключ группировки и ссылки на события |
| Ключ группировки | `grouping_key` | Incident | Ключ, по которому сигналы объединяются в один открытый инцидент |
| Тип инцидента | `IncidentType` | Incident | Класс ситуации (проникновение, пожар, отказ оборудования), определяющий сценарий и SLA |
| Инцидент | `Incident` | Incident | Ситуация, требующая реакции оператора. Центральный агрегат продукта |
| Приоритет | `Priority` | Incident | Срочность инцидента: `P1` (наивысший) - `P4` |
| Хронология | `Timeline` | Incident | Упорядоченный журнал всего, что произошло с инцидентом |
| Решение инцидента | `Resolution` | Incident | Итог работы: `confirmed` (реальная ситуация), `false_alarm`, `test`, `duplicate` |
| Эскалация | `Escalation` | Response | Привлечение следующего уровня ответственных при нарушении SLA |
| Политика эскалации | `EscalationPolicy` | Response | Набор SLA и уровней эскалации, привязанный к типу инцидента и приоритету |
| SLA | `Sla` | Response | Предельное время на принятие (`ack`) или решение (`resolve`) инцидента |
| Сценарий реагирования | `ResponsePlan` | Response | Версионированный регламент действий в виде графа шагов. В интерфейсе - «сценарий» или SOP |
| Шаг | `Step` | Response | Элемент сценария: инструкция, чек-лист, решение, команда, уведомление, ожидание, эскалация |
| Обязательный шаг | `mandatory` | Response | Шаг, без завершения которого инцидент нельзя решить |
| Запуск сценария | `ResponseRun` | Response | Исполнение конкретной версии сценария по конкретному инциденту |
| Команда | `Command` | Response | Запрос на воздействие на устройство через коннектор (заблокировать дверь, поставить на охрану) |
| Критичная команда | `critical` | Response | Команда, требующая подтверждения вторым пользователем |
| Уведомление | `Notification` | Response | Сообщение получателю по каналу: в приложении, email, webhook |
| Пользователь | `User` | Identity & Access | Человек, вошедший через Keycloak |
| Роль | `Role` | Identity & Access | Набор прав: `operator`, `supervisor`, `admin`, `integrator`, `auditor`, `manager` |
| Область доступа | `AccessScope` | Identity & Access | Набор площадок и зон, в пределах которых действует роль пользователя |
| Запись аудита | `AuditRecord` | Audit | Неизменяемая запись о действии субъекта над объектом, включённая в цепочку хэшей |
| Контрольная точка | `AuditCheckpoint` | Audit | Периодически фиксируемый хэш вершины цепочки аудита |
| Конверт | `Envelope` | Platform | Единая обёртка каждого сообщения Kafka: идентификатор, тенант, тип и версия схемы, времена, трассировка, полезная нагрузка |
| DLQ | `DeadLetter` | Platform | Сообщение, которое этап не смог обработать, с указанием причины |
| Проекция | `Projection` | Reporting / API | Read-модель, построенная из топиков Kafka и восстанавливаемая их проигрыванием |
