# Стратегия качества и верификации

Версия 0.1 · Шаг плана 0.7 · Статус: черновик

Как доказывается соответствие целям разделов 1.3 (SLO) и 1.4 (инженерное качество) плана, сценариям приёмки S1-S13 и требованиям безопасности. Связанные документы:

| Документ | Содержание |
|---|---|
| [verification.yaml](verification.yaml) | Реестр (источник истины): цели, наборы тестов, нагрузочные и хаос-эксперименты, бенчмарки, fitness functions, ручные процедуры |
| [verification-matrix.md](verification-matrix.md) | Матрица «цель -> методы -> барьер», генерируется задачей `task docs:verification:gen` |
| [reconciliation.md](reconciliation.md) | Методика сквозной сверки потерь и дубликатов |
| [latency-measurement.md](latency-measurement.md) | Методика замера задержек по event time |
| [ADR-031](../adr/0031-verification-tooling.md) | Инструменты верификации |

Задача `task docs:verification` проверяет DoD шага 0.7: каждая строка таблиц 1.3 и 1.4 плана и каждый сценарий S1-S13 имеют метод проверки с автоматическим барьером или ручной процедурой.

---

## 1. Принципы

1. **Доказательство, а не декларация.** Каждая цель имеет измеримый порог, метод и место, где порог проверяется автоматически.
2. **Сдвиг влево.** Максимум проверок - в быстрых уровнях: доменное ядро, свойства, симуляция. Дорогие уровни (кластер, 24 ч) подтверждают то, что нельзя проверить раньше.
3. **Детерминизм.** Доменное ядро и конвейер тестируются детерминированно (ADR-016, шаг 2.7); любая найденная ошибка воспроизводится по зерну.
4. **Один вход.** Все проверки - задачи Task (ADR-030); CI вызывает те же задачи, что и разработчик.
5. **Барьер, а не отчёт.** Нарушение порога блокирует слияние или выпуск; исключения оформляются явно в реестре как известное ограничение.
6. **Наблюдаемость как инструмент проверки.** Нагрузочные и хаос-тесты оценивают результат по тем же метрикам и трассировкам, что и эксплуатация.

## 2. Уровни тестирования

| Уровень | Что проверяет | Инструменты | Где выполняется | Скорость |
|---|---|---|---|---|
| Unit | Доменное ядро и чистые функции | GoogleTest, GMock | PR | секунды |
| Property-based | Инварианты агрегатов и модели состояний на случайных последовательностях команд | RapidCheck | PR | секунды |
| Component | Сервис с реальными адаптерами против контейнеров Kafka, PostgreSQL, Redis, ClickHouse | GoogleTest + окружение шага 1.4 | PR | минуты |
| Contract | Совместимость контрактов; соответствие API OpenAPI; соответствие коннектора протоколу (conformance kit) | buf, Schema Registry, Schemathesis, conformance kit | PR | минуты |
| Simulation | Конвейер в одном процессе с эмуляцией Kafka и хранилищ, внесением сбоев, управляемым временем | Стенд шага 2.7 | PR (короткий), ночь (тысячи прогонов) | минуты - часы |
| Integration | Сквозной поток в Docker Compose: от симулятора до консоли | Task + Compose + API-тесты | PR (смоук), ночь | минуты |
| E2E UI | Сценарии оператора и администратора в браузере | Playwright | ночь, выпуск | минуты |
| Benchmark | Пропускная способность и задержка горячих компонентов против базовой линии | Google Benchmark | PR (затронутые), ночь | минуты |
| Load | Пропускная способность и SLO задержки под нагрузкой | Симулятор (генератор нагрузки), метрики Prometheus | ночь (сокращённый профиль), выпуск (полный) | часы |
| Soak | Устойчивость 24 ч: утечки, рост лагов, деградация | Симулятор, метрики | выпуск | 24 ч |
| Chaos | Поведение при отказах: потери, дубликаты, RTO, RPO | Toxiproxy, остановка процессов и узлов, сверка | ночь (базовый набор), выпуск (полный) | часы |
| Security | SAST, зависимости и образы, DAST, фаззинг, TLS, проверка прав | clang-tidy, Trivy, OWASP ZAP, libFuzzer, testssl.sh | PR (SAST, зависимости), ночь, выпуск | минуты - 24 ч |
| Fitness functions | Архитектурные правила | Скрипты `tools/`, задачи Task | PR | секунды |
| Manual | То, что нельзя автоматизировать: установка сторонним инженером, учения по восстановлению, пентест | Регламенты | выпуск | дни |

### 2.1 Пирамида и доля проверок

Ориентир по числу тестов: unit и property-based - большинство; component и contract - десятки на сервис; simulation - сценарии сбоев на каждый поток данных; integration и E2E - по сценариям приёмки; load, soak, chaos - фиксированный каталог экспериментов в [verification.yaml](verification.yaml).

### 2.2 Тестирование доменного ядра

- Каждый инвариант из [aggregates.md](../domain/aggregates.md) - отдельный тест и, где применимо, свойство: «для любой допустимой последовательности команд инвариант соблюдён».
- Модели состояний ([state-models.md](../domain/state-models.md)) проверяются исчерпывающе: каждый переход разрешён или отклонён с ожидаемым кодом ошибки.
- Время и идентификаторы - через порты `Clock` и `IdGenerator`; в тестах детерминированы.

## 3. Стенды

| Стенд | Состав | Назначение |
|---|---|---|
| `E-DEV` | Машина разработчика: Docker Compose (шаг 1.4), Kafka 1 брокер | Unit, component, integration, отладка |
| `E-CI` | Раннеры CI с тем же Compose | Барьеры PR и ночные прогоны в сокращённом профиле |
| `E-LOCAL` | Эталонный сервер «одна машина» ([scaling.md](../architecture/scaling.md#54-эталонные-стенды)) | Функциональные E2E, нагрузка профиля одной машины |
| `E-CLUSTER` | Эталонный кластер на VM: 3 узла инфраструктуры, 2 узла приложений, узел наблюдаемости | Полная нагрузка, soak, chaos, обновление |

Профили нагрузки: `LOAD-50K` ([acceptance-spec.md](../product/acceptance-spec.md#общие-условия)), `LOAD-10K` для одной машины, `LOAD-5K` для ночных прогонов в CI.

## 4. Барьеры

| Барьер | Когда | Что блокирует | Состав |
|---|---|---|---|
| **PR** | Каждый merge request | Слияние | `task check`; сборка с `-Werror`; clang-tidy; unit, property, component, contract; санитайзеры ASan+UBSan и TSan; покрытие; бенчмарки затронутых компонентов (регрессия > 5%); короткая симуляция; смоук integration; fitness functions; SAST и проверка зависимостей |
| **Nightly** | Ежесуточно на `master` | Следующий выпуск, создаёт задачу при падении | Длинная симуляция (10 000 прогонов); integration и E2E; нагрузка `LOAD-5K`/`LOAD-10K`; базовый хаос-набор; фаззинг 1 ч на каждую цель; сканирование образов |
| **Release** | Кандидат выпуска | Выпуск | Полная нагрузка `LOAD-50K`; пик ×1,5; soak 24 ч; полный хаос-набор на `E-CLUSTER`; обновление N -> N+1 и откат; DAST; фаззинг 24 ч; проверка TLS; ручные процедуры; SBOM и подписи |

Правило: красный барьер PR не обходится; красный nightly блокирует выпуск до исправления или явной записи известного ограничения.

## 5. Нестабильные тесты

- Тест, упавший и прошедший без изменений кода, считается нестабильным и помечается в течение суток.
- Нестабильный тест исправляется или удаляется в течение 5 рабочих дней; карантин не дольше этого срока и виден в отчёте CI.
- Тесты не используют `sleep` для синхронизации; ожидание - по условию с дедлайном.
- Распределённые сценарии с недетерминизмом переносятся в симуляцию, где они детерминированы.

## 6. Покрытие

| Область | Порог | Измерение |
|---|---|---|
| Доменное ядро (`libs/domain/*`) | ≥ 90% строк, ≥ 80% ветвей | llvm-cov по unit и property-тестам |
| Инфраструктурный код (`libs/platform/*`, `services/*/adapters`) | ≥ 75% строк | llvm-cov по unit, component и integration |
| Веб-клиент | ≥ 80% строк для логики (stores, API-клиент, протокол realtime) | Vitest coverage |

Покрытие - необходимое, но не достаточное условие: доменные инварианты дополнительно проверяются свойствами и симуляцией.

## 7. Тестовые данные

- Генерируются симулятором и фикстурами из кода; персональные данные в тестах только синтетические.
- Каждый сценарий приёмки имеет фикстуру объекта (площадка, здания, зоны, устройства), правил и сценариев реагирования; фикстуры версионируются в репозитории.
- Нагрузочные профили описаны декларативно (число устройств, распределение по площадкам, интенсивности по типам событий, пики) и воспроизводимы по зерну.

## 8. Отчётность

- Каждый прогон CI публикует: результаты тестов, покрытие, бенчмарки против базовой линии, отчёты сверки и задержек для нагрузочных и хаос-тестов.
- Отчёт выпуска (шаг 11.3) собирает статус по каждой цели [verification-matrix.md](verification-matrix.md): подтверждено, известное ограничение с планом устранения.
