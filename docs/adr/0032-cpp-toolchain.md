# ADR-032. C++ toolchain: clang 21 и libc++, Conan 2, CMake пресеты, контейнер сборки

- **Статус:** Принято
- **Дата:** 2026-10-06
- **Шаг плана:** 1.1
- **Связанные:** ADR-001, ADR-030, ADR-031, требования SR-23 и SR-24 ([threat-register.md](../security/threat-register.md))

## Контекст

Сервер пишется на C++23 (решение 0.1 плана) и должен поставляться для Debian 12 и Astra Linux 1.8 с воспроизводимыми артефактами (DoD шага 1.1). Штатные компиляторы платформ устарели для C++23: в Debian 12 - GCC 12 и clang 14, в Astra Linux 1.8.6 - GCC 12 и clang 16. Обе платформы используют glibc 2.36 и бинарно совместимы. Хост разработчика может быть любым Linux.

Попытка поставить toolchain из apt.llvm.org (репозиторий bookworm) непосредственно на Astra Linux 1.8.6 упирается в конфликт пакетов `libc++1` с репозиториями Astra. Важно различать платформу сборки и платформы выполнения: исполняемый файл, собранный с glibc 2.36 и статически скомпонованным libc++, работает на любой системе с glibc 2.36 и новее.

## Рассмотренные варианты

### Компилятор и стандартная библиотека

| Вариант | Плюсы | Минусы |
|---|---|---|
| Системный GCC 12 и libstdc++ 12 | Ничего не ставить | Неполный C++23: нет `<print>`, ряда возможностей библиотеки и языка |
| GCC 14 или 15, собранный самостоятельно | Свежий GCC | Сборка и сопровождение своего компилятора; тянет новый libstdc++, которого нет на целевых системах |
| clang 21 и системный libstdc++ 12 | Свежий компилятор | Библиотека остаётся на уровне GCC 12 |
| **clang 21 и libc++ 21 из apt.llvm.org, статическая компоновка libc++** | Полный C++23 в языке и библиотеке; один toolchain для обеих платформ (репозиторий bookworm подходит для Astra 1.8); исполняемые файлы не требуют libc++ на целевой системе; clang-tidy, санитайзеры, llvm-cov из того же выпуска | Все зависимости собираются из исходников с libc++ |

### Платформа сборки

| Вариант | Плюсы | Минусы |
|---|---|---|
| Сборка на каждой целевой платформе (Debian 12 и Astra 1.8) | Сборка «родным» окружением | Конфликты пакетов toolchain на Astra; два комплекта кэшей зависимостей; разные артефакты для одной версии |
| Только современная платформа (Debian 13, Ubuntu 24.04+) | Свежие пакеты без внешних репозиториев | Артефакты с новой glibc не запускаются на Debian 12 и Astra 1.8 - потеря целевых платформ плана |
| **Сборка в контейнере на самой старой целевой glibc (Debian 12), проверка запуском на каждой целевой платформе** | Один набор артефактов для всех платформ; современный компилятор; проверяется то, что поставляется | Сборка на Astra не выполняется; при требовании сборки на Astra (например, сертификация) - пересмотр отдельным ADR |

### Зависимости

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Conan 2 (решение плана), сборка из исходников профилем проекта, lock-файл** | Одинаковые флаги и стандартная библиотека у всех зависимостей; версии и ревизии рецептов закреплены | Первая сборка зависимостей занимает десятки минут (кэшируется) |
| Пакеты дистрибутива | Быстро | Старые версии, разные на Debian и Astra; libstdc++ |
| vcpkg | Аналог Conan | Противоречит решению плана |

## Решение

1. **Компилятор:** clang 21, libc++ 21, lld 21 из apt.llvm.org; стандарт C++23 без расширений; libc++ и libc++abi компонуются в исполняемые файлы статически (`-static-libstdc++`), glibc - динамически (2.36, общая для Debian 12 и Astra 1.8).
2. **Контейнер сборки** `tools/toolchain/Dockerfile` на базе Debian 12 (`debian:bookworm`, закреплён по дайджесту в корневом Taskfile). В образе: clang, clang-tidy, clang-format, llvm-cov, CMake, Ninja, Conan (закреплённые версии в venv), ccache, buf, Task. Тег образа - хэш Dockerfile. Этот же образ - контейнер разработчика (`.devcontainer/`).
3. **Целевые платформы** - Debian 12 и Astra Linux 1.8 (образ `registry.astralinux.ru/library/astra/ubi18`, закреплён по дайджесту). Задача `task cpp:runtime-test` запускает все тестовые исполняемые файлы и `psimctl` в чистых образах платформ без toolchain и проверяет отсутствие зависимости от разделяемого libc++.
4. **Зависимости:** Conan 2, профиль `tools/conan/profiles/clang21-libcxx` для хоста и сборки; статические библиотеки; версии в `conanfile.py`, разрешённый граф с ревизиями рецептов - в `conan.lock`. Зависимости собираются только в Release; конфигурации проекта отображаются на Release через `CMAKE_MAP_IMPORTED_CONFIG_*`. Это вдвое сокращает время сборки зависимостей; отладка внутри зависимостей не требуется.
5. **CMake:** пресеты `debug`, `release`, `relwithdebinfo`, `asan` (ASan + UBSan), `tsan`, `coverage`; Ninja; ccache; каталоги сборки `build/debian12/<пресет>`; кэши Conan и ccache - в `.cache/debian12/`.
6. **Флаги проекта:** строгие предупреждения и `-Werror` для собственного кода; сгенерированный и сторонний код компилируется без предупреждений проекта. Усиление защиты во всех конфигурациях: `-fstack-protector-strong`, `-fstack-clash-protection`, `-fcf-protection=full`, PIE, полный RELRO, неисполняемый стек, `_FORTIFY_SOURCE=3` вне Debug, режим усиления libc++ (`_LIBCPP_HARDENING_MODE`: debug в Debug, fast в остальных).
7. **Воспроизводимость:** `-ffile-prefix-map` для исходного и сборочного каталогов, `--build-id=sha1`, запрет `__DATE__` и `__TIME__` (`-Wdate-time`), `SOURCE_DATE_EPOCH=0`, в артефакты встраивается только версия и коммит; проверка - `task cpp:reproducible`: две сборки release в разных каталогах без ccache побайтно сравниваются.
8. **Генерация кода контрактов:** protoc и `grpc_cpp_plugin` берутся из контекста сборки Conan, поэтому версии генератора и среды выполнения совпадают; сторонние импорты proto (`google/api`, `buf/validate`) вендорятся задачей `contracts:vendor` и проверяются на актуальность.
9. **Санитайзеры:** зависимости не инструментированы. Для `asan` этого достаточно (тесты проходят). Для `tsan` - нет: заголовки protobuf в режиме TSan включают проверки (`TSanRead`), которые требуют библиотеку protobuf, собранную с TSan, и дают ложные `heap-use-after-free`. Пресет `tsan` становится рабочим на шаге 1.2 вместе с инструментированной сборкой зависимостей (отдельная настройка Conan, чтобы двоичные пакеты не смешивались).

## Последствия

- `task cpp:build`, `task cpp:test` с параметром `PRESET` - одна команда на любом хосте с Docker; внутри контейнера команды выполняются напрямую.
- Первая сборка зависимостей - десятки минут; затем кэш Conan и ccache.
- Пакеты для Debian и Astra (шаг 1.3) не требуют libc++ на целевой системе.
- Новые зависимости добавляются в `conanfile.py` с обновлением `conan.lock` (`task cpp:lock`).

## Проверка

`task cpp:test` - чистая сборка и тесты; `task cpp:runtime-test` - тесты и `psimctl` на Debian 12 и Astra Linux 1.8, без разделяемого libc++; `task cpp:reproducible` - побайтное совпадение артефактов.
