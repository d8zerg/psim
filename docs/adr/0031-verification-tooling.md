# ADR-031. Инструменты верификации

- **Статус:** Принято
- **Дата:** 2026-10-06
- **Шаг плана:** 0.7 (реализация - 1.2-1.4, 2.7, 3.1, 4.3, 10.1-10.3)
- **Связанные:** ADR-030, [strategy.md](../quality/strategy.md), [verification.yaml](../quality/verification.yaml)

## Контекст

План фиксирует GoogleTest и GMock, Google Benchmark, libFuzzer, Vitest и Playwright. Стратегия качества требует ещё: проверки свойств инвариантов, измерения покрытия, генератора нагрузки без искажения хвостов задержки, внесения сетевых сбоев, контрактных тестов REST, сканирования зависимостей и образов, DAST, проверки TLS. Все инструменты запускаются задачами Task (ADR-030), предпочтительно в контейнерах с закреплёнными версиями; лицензии должны допускать использование в CI коммерческого продукта.

## Рассмотренные варианты и решение

| Задача | Выбрано | Рассмотрено | Почему |
|---|---|---|---|
| Property-based тесты C++ | **RapidCheck** (BSD-2) | Свои генераторы на GoogleTest; fuzz-тесты как свойства | Генераторы, сжатие контрпримеров, интеграция с GoogleTest |
| Покрытие C++ | **llvm-cov** (source-based coverage clang) | gcov/lcov | Тот же toolchain clang; точное покрытие ветвей |
| Гистограммы задержек | **HdrHistogram_c** (CC0/BSD) + нативные гистограммы Prometheus | Только бакеты Prometheus | Точные хвосты в отчётах без погрешности бакетов |
| Генератор нагрузки | **Собственный симулятор (шаг 4.3)**, открытая модель нагрузки | k6, Gatling, ghz | Протокол коннекторов с кредитами и двунаправленным потоком, порядковые номера для сверки, сценарные вставки с оракулом; сторонние генераторы не поддерживают это без собственного кода |
| Нагрузка консолей и REST | **k6** (AGPL, используется как внешний инструмент без распространения) с WebSocket | Gatling, Locust | Сценарии на JS, WebSocket, метрики с перцентилями; не входит в поставку |
| Сетевые сбои | **Toxiproxy** (MIT) + `tc netem` на узлах стенда | Pumba, Chaos Mesh, Litmus | Kubernetes вне MVP; Toxiproxy управляется API из тестов, работает в Compose и на VM |
| Отказы процессов и узлов | **Сценарии хаоса как задачи Task**: `docker kill`, `systemctl kill`, отключение VM через API гипервизора стенда | Chaos Mesh, Litmus | То же; эксперименты версионируются вместе с кодом и вызывают сверку |
| Контрактные тесты REST | **Schemathesis** (MIT) по `psim-api-v1.yaml` | Dredd, собственные тесты | Генерация запросов из OpenAPI, проверка схем ответов, стабильная поддержка OpenAPI 3 |
| Доступность интерфейса | **axe-core** (MPL-2.0) в Playwright | Lighthouse | Встраивается в E2E, детерминированные правила |
| Зависимости, лицензии, образы | **Trivy** (Apache 2.0) | Grype + Syft, OWASP Dependency-Check | Один инструмент для SBOM, уязвимостей, лицензий и образов |
| DAST | **OWASP ZAP** (Apache 2.0) | Burp Suite | Открытая лицензия, импорт OpenAPI, автоматизация |
| Проверка TLS | **testssl.sh** (GPL-2.0, внешний инструмент) | sslyze | Полнота проверок, запуск в контейнере |
| Статический анализ безопасности | **clang-tidy** (профили bugprone, cert, performance, проектные правила) | CodeQL, Coverity | Уже в toolchain; CodeQL и Coverity ограничены лицензиями для закрытого кода |

Версии инструментов фиксируются в корневом Taskfile (образы) или lock-файлах (библиотеки) на шагах, где инструмент впервые используется ([verification-matrix.md](../quality/verification-matrix.md#6-методы-по-шагам-плана)).

## Последствия

- Генератор нагрузки - часть продукта (эталонный коннектор-симулятор), поэтому он развивается вместе с протоколом и оракулом сверки.
- Инструменты под AGPL и GPL (k6, testssl.sh) используются только как внешние программы в CI и на стендах и не входят в поставку.
- Хаос-эксперименты переносимы между Compose и VM; переход на Kubernetes потребует отдельного ADR.

## Проверка

`task docs:verification`: каждый метод реестра имеет задачу Task и шаг плана, создающий его.
