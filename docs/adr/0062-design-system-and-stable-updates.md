# ADR-062. Дизайн-система и стабильное обновление интерфейса

- **Статус:** Принято
- **Связанные:** [ADR-037](0037-web-monorepo.md), [ADR-060](0060-realtime-delivery.md), [ADR-061](0061-live-access-validation.md)

## Контекст

Оператор работает с потоком изменений длительное время. Замена списка полноэкранным индикатором, сброс выбора и светлый кадр при запуске мешают работе. Общие элементы должны одинаково передавать приоритет, качество связи и состояние операции, поддерживать клавиатуру, обе темы и ru/en.

В качестве локального образца изучен проект `psim_arch/web`: раннее применение настроек, семантические токены, сохранение данных при фоновой загрузке, стабильные идентификаторы строк и диалоги с управлением фокусом. Его API, модули и предметные модели не переносятся.

## Решение

1. `@psim/design-system` владеет токенами Tailwind CSS 4, компонентами в стиле shadcn/ui и паттернами состояний. Формы используют связанные подписи и ошибки, статусы - текст и семантический цвет. Подтверждение реализовано через Radix Alert Dialog с удержанием и возвратом фокуса. Для простого одиночного выбора используется доступный нативный select. Статусный цвет имеет отдельные формы для текста и для заливки: светлый текстовый цвет тёмной темы не используется как фон критичного действия. Декоративные границы панелей отделены от границ контролов, которые сохраняют контраст 3:1.
2. По умолчанию применяется тёмная тема. Тема, плотность, язык и согласие на звук сохраняются в `psim.ui`. Синхронный внешний `theme-init.js` применяет проверенные значения до запуска приложения и загрузки его модулей. Недоступное или повреждённое хранилище не блокирует работу. Тема ОС не отменяет явный тёмный режим по умолчанию.
3. Плотность изменяет высоту контролов, строк и отступы через общие переменные. Обычный режим предназначен для комфортного чтения, компактный - для рабочего места с большим объёмом данных. Фокус сохраняет контрастный контур; режим reduced motion отключает движение, forced colors сохраняет границы.
4. Первичная загрузка показывает зарезервированную область. Повторная загрузка сохраняет текущие строки и показывает отдельный статус. Ошибка не удаляет последний успешный результат; он явно помечается как устаревший, действия блокируются владельцем страницы. Скелетон не возвращается при каждом refetch.
5. Ключом строки служит идентификатор предметного объекта. Версия и состояние соединения не входят в React key. Одинаковые строки повторного снимка сохраняют ссылочную идентичность; строка ленты мемоизирована. Высота панели фильтров и области статуса стабильна; `scrollbar-gutter` не позволяет странице менять ширину при появлении прокрутки.
6. Язык ru/en задаётся типизированными словарями с раздельными пространствами продукта и примеров. Выбранные словари загружаются до первого отображения. Смена языка ждёт загрузки перевода, затем одновременно меняет подписи и `html.lang`, сохраняя смонтированный экран; ошибка сохраняет прежний язык и ввод. Идентификаторы, коды и пользовательские данные не переводятся. Презентационные настройки не содержат bearer или данные серверного кэша.
7. Оповещение всегда имеет текст и статическое визуальное выделение. Звук выключен до явного согласия; короткий сигнал создаётся Web Audio после действия пользователя. Ошибка воспроизведения сохраняет визуальное сообщение. Реальный поток оповещений и группировка подключаются вместе с консолью оператора.
8. `design-system.html` - отдельная точка входа Vite с интерактивными макетами на демонстрационных данных. Она использует общие компоненты приложения. Исходный бюджет минимальной витрины - 180 КБ JS gzip и 15 КБ CSS gzip; расширение и измерения описаны в [ADR-065](0065-ui-loading-budgets.md). Начальная загрузка рабочей консоли отдельно ограничена 150 КБ JS gzip по транзитивным imports манифеста Vite; код макетов и диалогов не должен попадать в неё без использования. Прежний суммарный бюджет 150 КБ увеличивается из-за добавления полноценной витрины, локализации и доступных примитивов; начальная загрузка сохраняет прежнее ограничение. Подключение маршрутизации и ролевых модулей остаётся частью оболочки приложения.

## Границы

Макеты покрывают S2, S6-S9 и S13 и не выполняют рабочие команды или изменения каталога. Карточка критичной команды показывает ожидание подтверждения другого старшего смены; передача ответственности ожидает согласия получателя. Маркер потери связи не подменяется последним известным online. Проверки интерфейса не заменяют серверную авторизацию.

Сохранение предыдущих данных допустимо только в прежнем контексте доступа. При смене пользователя, тенанта или областей оболочка обязана удалить прежний серверный кэш и закрыть подписки. Нельзя глобально переносить `placeholderData` между различными областями, показывая чужие строки.

## Проверка

`task web:check`, `task web:e2e`, `task web:a11y` и регрессия M1 `task flow:test`. Проверяются темы, плотности, ru/en, контраст, клавиатура и диалог, DOM-идентичность, фокус, положение строк при refetch и применение настроек до выполнения модулей приложения.
