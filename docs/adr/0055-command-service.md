# ADR-055. Сервис команд устройствам

- **Статус:** Принято
- **Связанные:** ADR-008, ADR-017, ADR-018, ADR-020

## Контекст

Command Service управляет жизненным циклом команды и проверяет права инициатора. Connector Gateway доставляет команду сессии, SDK предотвращает повторное исполнение. После разрыва сессии результат действия может быть неизвестен.

## Решение

- Чистая модель `libs/domain/response` определяет переходы и конечные состояния. PostgreSQL, схема `command`, хранит команды, отпечатки запросов, inbox, outbox и локальные проекции каталога и инцидентов из Kafka. Сервис не читает схемы других сервисов.
- Авторизация использует общую библиотеку RBAC + ABAC. Тип устройства определяет возможность, параметры и критичность; клиент не может отключить подтверждение. Критичную команду подтверждает другой пользователь с ролью supervisor и доступом к устройству и связанному инциденту.
- Идентификатор команды совпадает с Idempotency-Key. Одинаковый запрос одного инициатора возвращает актуальную команду; другое содержимое или инициатор отклоняются. Изменения состояния, аудит и события ответа сохраняются одной транзакцией с outbox.
- Перед отправкой сервис читает SessionRegistry Valkey. Отсутствующая сессия даёт `COMMAND_CONNECTOR_OFFLINE`; ошибка чтения не считается отсутствием. Доставка содержит идентификатор выбранной сессии, шлюз принимает её только для этой сессии. Результат шлюза также содержит идентификатор сессии.
- `SENT` означает долговечно поставленную в outbox доставку; `ACKNOWLEDGED` требует квитанции коннектора. До отправки команду можно отменить. Подтверждение ограничено дедлайном. Потеря выбранной сессии после отправки даёт конечный `UNKNOWN` и `COMMAND_OUTCOME_UNKNOWN`; автоматическая отправка в новую сессию запрещена. Результат после конечного состояния не меняет его.
- Сервис публикует `CommandUpdated` в `psim.response.events.v1`. Incident Service сохраняет эти изменения в хронологии без изменения жизненного цикла инцидента.
- Совместимые расширения Protobuf добавляют `UNKNOWN`, код ошибки и поля сессии. Старые доставки без сессии сохраняют прежнее поведение шлюза; новый Command Service всегда указывает сессию.

## Альтернативы

- Прямое чтение таблиц каталога и шлюза нарушает владение данными.
- Автоматическое повторение после переподключения не позволяет отличить потерянный ответ от неисполненной команды.
- Хранение команд только в памяти не обеспечивает восстановление дедлайнов и результатов после остановки процесса.

## Последствия

Локальные проекции должны получить ресурс до приёма команды. Valkey нужен перед отправкой и при проверке смены сессии. Каждая активная команда имеет ограниченный срок жизни; при недоступности инфраструктуры обработка возобновляется после восстановления.
