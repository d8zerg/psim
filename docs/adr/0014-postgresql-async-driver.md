# ADR-014. Асинхронный драйвер PostgreSQL

- **Статус:** Предложено (принимается в начале шага 2.4)
- **Дата:** 2026-10-06
- **Шаг плана:** 2.4
- **Связанные:** ADR-008, ADR-016

## Контекст

Сервисы работают на Boost.Asio с корутинами (ADR-016) и не должны блокировать потоки цикла событий на запросах к БД. Нужны пул соединений, транзакции, пакетная вставка (`COPY`), `LISTEN/NOTIFY` (реле outbox), pipeline mode для снижения задержек и TLS. Зрелого асинхронного C++-драйвера на Asio нет (риск раздела 20 плана).

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| libpqxx | Зрелая, удобный C++ API | Синхронная: нужен пул потоков для блокирующих вызовов; нет pipeline mode в асинхронном виде |
| ozo (Yandex) | Асинхронный на Asio | Проект не развивается; старые стандарты C++ |
| Собственная реализация протокола PostgreSQL | Полный контроль | Большой объём: аутентификация SCRAM, TLS, типы, `COPY` |
| **Тонкий собственный адаптер над libpq в неблокирующем режиме, интегрированный с Asio** | libpq - эталонная реализация протокола, TLS, SCRAM; неблокирующий API и pipeline mode (PostgreSQL 14+); сокет соединения отслеживается `asio::posix::stream_descriptor` | Своя обвязка: пул, корутинный API, разбор результатов |
| Синхронная libpq в выделенном пуле потоков | Проще всего | Потоки на каждое соединение; хуже задержки и масштаб |

## Предлагаемое решение

Тонкий адаптер `libs/platform/pg` над libpq: `PQsetnonblocking`, `PQenterPipelineMode`, ожидание готовности сокета через Asio; корутинный API (`co_await conn.query(...)`), пул с дедлайнами, транзакции с уровнями изоляции, `COPY FROM STDIN` для пакетной вставки, `LISTEN/NOTIFY`, подготовленные выражения. Отображение типов - ограниченный набор (int, bigint, text, uuid, timestamptz, jsonb, bytea, массивы).

## Последствия

- Объём работ шага 2.4 включает адаптер; доменный код от него изолирован портами репозиториев.
- Запасной вариант при проблемах - синхронная libpq в пуле блокирующих операций за тем же интерфейсом.

## Проверка

Интеграционные тесты против PostgreSQL в Docker: разрыв соединения, переключение мастера, отмена по дедлайну; бенчмарк пропускной способности вставки и задержки запроса.
