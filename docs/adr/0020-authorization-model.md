# ADR-020. Модель авторизации: RBAC + ABAC, точка принятия решений

- **Статус:** Предложено (принимается в начале шага 7.4)
- **Дата:** 2026-10-06
- **Шаг плана:** 7.4
- **Связанные:** ADR-019, [roles-and-journeys.md](../product/roles-and-journeys.md), [aggregates.md](../domain/aggregates.md#6-identity--access)

## Контекст

Права определяются ролью (оператор, старший смены, администратор, интегратор, аудитор, руководитель) и областью доступа (площадки, зоны). Решение о доступе нужно на каждом REST-запросе, при фильтрации realtime-потока (тысячи событий в секунду на экземпляр) и в сервисах. Задержка решения - микросекунды; источник ролей - Keycloak.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Keycloak Authorization Services (UMA) | Централизованные политики | Сетевой вызов на решение; не годится для фильтрации потока |
| Open Policy Agent (Rego) как sidecar или сервис | Выразительный язык политик | Сетевой вызов или встраивание Go/Wasm в C++; лишняя подсистема |
| Cedar | Формально проверяемый язык | Реализация на Rust; FFI в C++ |
| **Собственная библиотека политик: роли из JWT, области доступа из атрибутов токена, таблица «роль × действие» + проверка области** | Решение в процессе за микросекунды; одна реализация в API Gateway и сервисах; таблица прав - данные, тестируется матрицей | Свой код; ограниченная выразительность (достаточна для MVP) |

## Предлагаемое решение

1. Роли - роли клиента Keycloak; области доступа - атрибуты пользователя или групп Keycloak, включаемые в токен доступа как claim `psim_scopes` (список площадок и зон).
2. Библиотека `libs/platform/access`: `decide(principal, action, resource{site_id, zone_id}) -> allow | deny(reason)`; запрет по умолчанию; таблица «роль × действие» - файл в `contracts/`, общий для сервера и веб-клиента (скрытие недоступных действий).
3. Проверка выполняется в API Gateway и повторно в сервисе-владельце (защита в глубину).
4. Каждый отказ - запись аудита `AccessDenied`.
5. Изменение области доступа вступает в силу при выдаче нового токена (срок жизни токена доступа - 5 мин).

## Последствия

- Размер токена растёт с числом зон в области; при больших областях - ссылка на набор областей вместо перечисления (решается в шаге 7.4).

## Проверка

Автоматическая матрица «роль × действие × область», включая негативные случаи (DoD шага 7.4).
