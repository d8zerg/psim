# ADR-021. Неизменяемый аудит на цепочке хэшей

- **Статус:** Предложено (принимается в начале шага 6.4)
- **Дата:** 2026-10-06
- **Шаг плана:** 6.4
- **Связанные:** [aggregates.md](../domain/aggregates.md#7-audit), S10

## Контекст

Журнал аудита должен обнаруживать любую модификацию или удаление записей, включая действия администратора БД (S10), и позволять независимую проверку экспортированной выборки.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Таблица только для добавления (права БД) | Просто | Суперпользователь БД изменит запись незаметно |
| **Линейная цепочка хэшей SHA-256 + периодические контрольные точки, экспортируемые вне БД** | Любое изменение или удаление обнаруживается; проверка простая и независимая | Последовательная запись на тенант (узкое место при росте) |
| Дерево Меркла с публикацией корней | Доказательства включения отдельных записей; параллелизм | Сложнее; доказательства включения в MVP не требуются |
| Внешний неизменяемый журнал (immudb и аналоги) | Готовый механизм | Новая подсистема в поставке |

## Предлагаемое решение

1. Цепочка на тенант: `hash_n = SHA-256(hash_{n-1} || canonical(record_n))`, `audit_seq` без пропусков; каноническая сериализация - детерминированный Protobuf записи.
2. Права БД: роль сервиса - только `INSERT` и `SELECT`; `UPDATE`, `DELETE`, `TRUNCATE` запрещены триггером и правами.
3. Контрольная точка каждые 5 мин или 10 000 записей: `(audit_seq, hash, время)`, подписанная ключом сервиса аудита; публикуется в `psim.audit.v1` и пишется в файл вне БД (каталог, указанный установщиком, рекомендуемо - другой носитель).
4. Проверка целостности: пересчёт цепочки от контрольной точки; отчёт с первым номером записи, где цепочка нарушена.
5. Экспорт выборки содержит записи, хэши соседних записей и ближайшие контрольные точки - достаточно для независимой проверки.
6. Один активный писатель цепочки на тенант (ключ топика `tenant_id`, одна партиция на тенант), второй экземпляр - резерв.

## Последствия

- Пропускная способность аудита ограничена одним писателем на тенант: тысячи записей в секунду пакетной вставкой - с запасом для MVP. Путь роста - цепочки на партицию с общей вершиной в контрольной точке ([scaling.md](../architecture/scaling.md#6-масштабирование-сверх-mvp)).

## Проверка

Тест: изменение, удаление и вставка записи напрямую в БД обнаруживаются с точностью до записи (DoD шага 6.4).
