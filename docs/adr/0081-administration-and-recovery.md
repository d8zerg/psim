# ADR-081. Нативные административные операции и резервные копии

- Статус: Принято
- Связанные решения: ADR-023, ADR-034, ADR-042, ADR-046, ADR-052, ADR-080

## Решение

`psimctl` реализует административные операции и восстановление с существующими библиотеками Kafka, PostgreSQL, S3, HTTPS и ClickHouse. Мониторинг выполняет отдельный компонент `psim-monitoring-agent` со своим пакетом, образом и жизненным циклом. Он использует платформенные клиенты и общую библиотеку файлового ввода-вывода, не зависит от CLI и не получает его операции восстановления. Образ агента использует минимальную закреплённую основу без административных утилит.

Исполнитель миграций выпуска входит в `psim-pg-migrate release`. C++ проверяет контрольные суммы, ведёт журнал выполненных операторов, удерживает блокировку и проверяет барьер schema epoch перед contract. Python-установщик доставляет проверенные артефакты и запускает нативный инструмент.

Физическая копия PostgreSQL создаётся штатными `pg_basebackup` и `pg_verifybackup`; WAL архивируется отдельным вызовом `psimctl backup wal-push`. Нативные утилиты запускаются без shell, с явными аргументами и окружением. CLI сохраняет действующие команды версии и примера контракта, а также предоставляет вход к прежним инструментам шлюза, миграций, аудита и проекций. Прежние имена сохраняются на один выпуск.

Копии хранятся в независимом S3, отдельно от рабочего SeaweedFS и bucket `psim-plans`. Учётная запись записи копий не получает чтение; отдельная учётная запись чтения и закрытый ключ доступны только при восстановлении. Объекты копий шифруются CMS AES-256-GCM с публичным сертификатом получателя и RSA-OAEP/SHA-256. Большие артефакты делятся на ограниченные части. Полный зашифрованный манифест публикуется последним. Неизвестный результат записи не считается успехом.

ClickHouse создаёт штатный `BACKUP` в отдельном временном диске. CLI шифрует архив и передаёт его во внешнее хранилище; временный диск не считается резервной копией. Внешнее хранилище и права должны быть настроены до включения расписания.

После физической копии фиксируется именованная точка восстановления, подтверждается архивирование её WAL, затем повторно копируются объекты планов. Срок защиты неподвязанных объектов - восемь суток; он должен превышать окно PITR и интервал копирования. Восстановление останавливается на целевой точке. Порядок - объекты -> PostgreSQL -> проверка файлов. Объекты без ссылок выводятся отчётом и автоматически не удаляются.

Диагностический replay и рабочая обработка DLQ имеют разные команды. Правила проигрываются существующим API с проверкой области и версий; локальный replay сценария использует чистый C++-исполнитель без рабочих клиентов. DLQ публикуется только с явным `--apply`, с атомарной фиксацией собственной позиции повтора. Изменение исходных consumer offsets не требуется.

Из-за необходимости штатных утилит образ `psimctl` использует закреплённую Debian-основу PostgreSQL. Ограничения non-root, read-only и отсутствия capabilities сохраняются. Это исключение для административного образа относительно минимальных образов прикладных сервисов по ADR-034.

## Проверка

Нативные модульные тесты, реальная транзакция Kafka для DLQ, независимые S3-процессы с разными правами, физическое восстановление PostgreSQL и проверка SHA-256 планов. Квалификация целевого внешнего хранилища, полного чистого стенда двух топологий, входа пользователей и восстановления доверия выполняется отдельным эксплуатационным учением. Небольшой контейнерный прогон не подтверждает эти критерии.
