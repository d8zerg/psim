# ADR-020. Модель авторизации: RBAC + ABAC, точка принятия решений

<!-- language-links -->
[English](../../adr/0020-authorization-model.md) | [Русский](0020-authorization-model.md)
<!-- /language-links -->

- **Статус:** Принято
- **Связанные:** ADR-019, [roles-and-journeys.md](../product/roles-and-journeys.md), [aggregates.md](../domain/aggregates.md#6-identity--access)

## Контекст

Права определяются ролью (оператор, старший смены, администратор, интегратор, аудитор, руководитель) и областью доступа (площадки, зоны). Решение о доступе нужно на каждом REST-запросе, при фильтрации realtime-потока (тысячи событий в секунду на экземпляр) и в сервисах. Задержка решения - микросекунды; источник ролей - Keycloak.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| Keycloak Authorization Services (UMA) | Централизованные политики | Сетевой вызов на решение; не годится для фильтрации потока |
| Open Policy Agent (Rego) как sidecar или сервис | Выразительный язык политик | Сетевой вызов или встраивание Go/Wasm в C++; лишняя подсистема |
| Cedar | Формально проверяемый язык | Реализация на Rust; FFI в C++ |
| **Собственная библиотека политик: роли из JWT, области доступа из атрибутов токена, таблица «роль × действие» + проверка области** | Решение в процессе за микросекунды; одна реализация в API Gateway и сервисах; таблица прав - данные, тестируется матрицей | Свой код; ограниченная выразительность (достаточна для MVP) |

## Решение

1. Роли - роли клиента Keycloak; области доступа - атрибуты пользователя или групп Keycloak, включаемые в токен доступа как claim `psim_scopes` (список площадок и зон).
2. Библиотека `libs/platform/authz`: `decide(principal, action, resource{site_id, zone_id}) -> allow | deny(reason)`; запрет по умолчанию; таблица «роль × действие» - `contracts/authz/actions.json`. CMake встраивает тот же файл в библиотеку; изменение политики запускает повторную конфигурацию. Веб-клиент может использовать файл для скрытия недоступных действий; решение сервера обязательно.
3. Проверка выполняется в API Gateway и повторно в сервисе-владельце (защита в глубину).
4. Библиотека возвращает код отказа; сервис-владелец сохраняет `access.denied` через собственный outbox отдельной транзакцией после отката отклонённого действия. Администратор без роли оператора не обрабатывает инциденты.
5. Область ресурса включает тенант, площадку и зону. Поддерживаются `*`, UUID площадки или зоны и формы `site:<uuid>`, `zone:<uuid>`; wildcard не обходит границу тенанта и роль. Актуальность JWT и областей проверяется через introspection с коротким кэшем; набор областей по ссылке обновляется без выдачи нового JWT ([ADR-061](0061-live-access-validation.md)). Для назначения и подтверждения передачи Incident Service отдельно читает текущую активность, роли и области получателя через Keycloak с правами `view-users` и `view-clients`; присутствие в браузере не используется. Отказ каталога пользователей запрещает изменение ответственности.

## Последствия

- JWT консоли содержит `psim_scope_set`; Keycloak возвращает области пользователя и групп через introspection. Inline-формат поддерживается для ограниченных наборов сервисных идентичностей.

## Проверка

Автоматическая матрица «роль × действие × область», включая негативные случаи: `task test:authz`. Общую реализацию контролирует `task arch:authz` (FF-22). Настройка и границы актуальности описаны в [руководстве](../security/authorization.md).
