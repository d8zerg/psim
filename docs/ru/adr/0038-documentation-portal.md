# ADR-038. Портал документации из репозитория

<!-- language-links -->
[English](../../adr/0038-documentation-portal.md) | [Русский](0038-documentation-portal.md)
<!-- /language-links -->

- **Статус:** Принято
- **Связанные:** ADR-026, ADR-030, ADR-034, метод FF-09 ([verification-matrix.md](../quality/verification-matrix.md))

## Контекст

Единый портал документации из репозитория - архитектура, ADR, модели C4, справочники OpenAPI, AsyncAPI и Protobuf, руководства; публикуется из CI. DoD: изменение контракта без обновления документации невозможно, так как справочники генерируются.

Исходные условия: документы - Markdown в `docs/` с относительными ссылками и якорями в стиле GitHub, проверяемыми `docs:links`; UML и C4 имеют единый формат PlantUML; контракты - OpenAPI и AsyncAPI, сгенерированные и проверяемые `task contracts:check`, справочник Protobuf в Markdown, реестры топиков и ошибок. Портал входит в поставку и должен открываться без интернета. Конвейер локальный, хостинг git - только хранилище кода (ADR-034).

## Рассмотренные варианты

### Генератор

| Вариант | Плюсы | Минусы |
|---|---|---|
| Docusaurus | React, MDX | MDX ломается на обычном Markdown с `<` и `{}`; тяжёлая сборка |
| VitePress | Быстрый, Node уже есть | Markdown компилируется в шаблоны Vue: `{{ }}` в тексте (Task, Go-шаблоны) требует экранирования |
| Zensical | Преемник Material, читает `mkdocs.yml` | Версия 0.0.x |
| **MkDocs 1.6 + Material 9.7** | Обычный Markdown без сюрпризов; строгий режим проверяет ссылки и якоря; поиск по-русски; зрелость | MkDocs 1.x не развивается, Material - в режиме сопровождения; путь миграции - Zensical (тот же `mkdocs.yml`) |

### Справочники

| Справочник | Источник | Как строится |
|---|---|---|
| REST | `contracts/openapi/psim-api-v1.yaml` | Локальный OpenAPI JSON и Redoc в HTML; скрипт и логотип Redoc включены в образ портала |
| Топики Kafka | `contracts/asyncapi/psim-topics.yaml` | Страница генерируется из документа AsyncAPI: топик, сообщение со ссылкой на Protobuf, ключ, партиции, retention, семантика, кто пишет и читает |
| Protobuf | `contracts/docs/proto-reference.md` | Генерируется и проверяется `contracts:check` |
| Коды ошибок | `contracts/errors/errors.yaml` | Страница генерируется из каталога |
| C4 | `docs/architecture/c4/L2-Containers.puml` | Семь представлений L1, L2, L3 и развёртывания хранятся в PlantUML с локальной стандартной библиотекой C4 |

### Диаграммы

PlantUML рендерится при сборке в SVG на белом фоне в закреплённом по digest образе без сети: портал не грузит рендерер, работает без сети, диаграммы читаются в тёмной и светлой теме. Изображение открывается в полном размере по щелчку.

## Решение

1. **`task docs:portal`** собирает `build/portal/site`: копирует `docs/` и README репозитория с сохранением раскладки (относительные ссылки работают), генерирует справочники, строит REST-справочник Redoc, рендерит PlantUML, выполняет `mkdocs build` в **строгом режиме** - битая ссылка или якорь останавливает сборку. Ссылки на файлы вне портала (proto, YAML, код) ведут в репозиторий на коммит сборки. Навигация строится из разделов `docs/README.md` плюс реестр ADR, справочники и раздел разработки - оглавление не ведётся вручную в двух местах.
2. **Без внешних ресурсов:** шрифты не загружаются, плагин `offline` Material не используется (он подключает скрипт с CDN), скрипт и логотип Redoc - локальные файлы с закреплёнными SHA-256. Ссылка на репозиторий не запрашивает статистику GitHub. Redoc строит страницу из локального контракта в браузере; предварительная отрисовка другим экземпляром React не используется.
3. **Образ портала** `tools/docs/portal/` (Python 3.13, MkDocs 1.6.1, Material 9.7.7, pymdown-extensions; Redoc с проверкой SHA-256) собирается локально, тег - хэш Dockerfile и требований.
4. **Публикация:** портал входит в каждый выпуск - `psim-platform-docs_<version>.tar` с SBOM (тема Material и Redoc, лицензии MIT) в подписанном каталоге `dist/` (ADR-034); локально - `task docs:serve` (`http://localhost:8000`). Отдельного хостинга нет.
5. **Самодостаточность:** постоянные цели качества находятся в отдельном реестре; требования безопасности связаны с компонентами, а не с последовательностью разработки. Документы конечного состояния содержат критерии и ограничения выпуска. Материалы разработки исключены из портала; `docs:release:check` проверяет копию репозитория и портал без них.
6. **Барьер:** `docs:portal` входит в `docs:check` (FF-09); этап `docs` конвейера включается при изменении документов и контрактов.

7. **Языки:** английский используется по умолчанию; русский содержит полные пары страниц, диаграмм, справочников и эксплуатационных инструкций. Реестр `docs/localization.yaml` сохраняет идентификаторы страниц и хэши проверенных источников. Термины сопоставлены в [глоссарии](../domain/glossary.md). Смена языка сохраняет соответствующую страницу и раздел; поиск остаётся в выбранном языке. [Порядок участия](../repository/CONTRIBUTING.md) определяет совместную проверку и повторную генерацию.

## Последствия

- Изменение контракта отражается в портале при следующей сборке; несогласованность OpenAPI, AsyncAPI и справочника Protobuf с proto ловит `contracts:check`, а ссылки и якоря - строгий режим.
- Сборка портала включает рендеринг UML/C4, генерацию справочников, Redoc и строгую проверку MkDocs. Время зависит от числа страниц и диаграмм.
- Переход на Zensical - когда он выйдет из 0.x; конфигурация совместима.

## Проверка

`task docs:portal`, `task docs:check`; отрицательная проверка: битая ссылка в документе даёт отказ строгого режима. Выпуск: `task release:dist`, `task release:verify` - архив портала подписан и описан SBOM.
