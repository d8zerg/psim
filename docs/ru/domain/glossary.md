# Глоссарий

<!-- language-links -->
[English](../../domain/glossary.md) | [Русский](glossary.md)
<!-- /language-links -->

Единый язык проекта. Термины используются одинаково в документации, коде, контрактах и интерфейсе. В коде применяется английское имя из столбца «Код».

## Общие правила

- Все идентификаторы сущностей - UUIDv7, если явно не указано детерминированное построение (см. [aggregates.md](aggregates.md), раздел 0).
- Принадлежность тенанту задаётся через `tenant_id` в доменной модели и конвертах сообщений. HTTP-запросы получают тенант из аутентифицированного субъекта.
- Время хранится в UTC с точностью до микросекунд. Различаются **время возникновения** (`occurred_at`, по часам источника) и **время приёма** (`received_at`, по часам платформы).

## Термины

| Термин EN | Термин RU | Код | Контекст | Определение |
|---|---|---|---|---|
| Tenant | `Тенант` | `Tenant` | Platform | Изолированная организация-владелец данных. В MVP один, но присутствует во всех ключах |
| Location | `Локация` | `Location` | Catalog | Узел иерархии защищаемого объекта: площадка, здание, этаж или зона |
| Site | `Площадка` | `Site` | Catalog | Корневая локация: территориально обособленный объект (завод, кампус, станция) |
| Building | `Здание` | `Building` | Catalog | Локация внутри площадки |
| Floor | `Этаж` | `Floor` | Catalog | Локация внутри здания; может иметь поэтажный план |
| Zone | `Зона` | `Zone` | Catalog | Наименьшая локация, к которой привязываются устройства и правила. Может находиться на этаже, в здании или прямо на площадке (наружные и периметральные зоны) |
| Floor plan | `Поэтажный план` | `FloorPlan` | Catalog | Изображение этажа с системой координат для размещения устройств |
| Device type | `Тип устройства` | `DeviceType` | Catalog | Класс устройств с набором источников и возможностей (датчик движения, дверь СКУД, камера) |
| Device | `Устройство` | `Device` | Catalog | Физическое или логическое оборудование, привязанное к зоне и обслуживаемое одним коннектором |
| Source | `Источник` | `Source` | Catalog | Канал событий устройства: шлейф, вход, детектор видеоаналитики. У устройства один или несколько источников. Ключ партиционирования сырых событий; идентификатор детерминирован ([ADR-029](../adr/0029-deterministic-source-id.md)) |
| Capability | `Возможность` | `Capability` | Catalog | Поддерживаемая устройством команда или режим (`lock`, `unlock`, `arm`, `ptz.preset`) |
| Connector | `Коннектор` | `Connector` | Catalog / Integration | Программный адаптер внешней системы к платформе, зарегистрированный в Connector Gateway с учётными данными mTLS и представленный в каталоге |
| Connector session | `Сессия коннектора` | `ConnectorSession` | Integration | Время жизни одного подключения коннектора к шлюзу |
| Raw event | `Сырое событие` | `RawEvent` | Integration | Событие в виде, переданном коннектором: идентификатор источника, порядковый номер, исходный код события, атрибуты |
| Source sequence | `Порядковый номер источника` | `source_seq` | Integration | Монотонно растущий номер события у источника. Используется для дедупликации и сквозной сверки |
| Mapping rule | `Правило отображения` | `MappingRule` | Event Processing | Декларативное правило перевода сырого события в тип таксономии и критичность |
| Event | `Событие` | `Event` | Event Processing | Нормализованное событие: тип таксономии, критичность, площадка, зона, устройство, источник |
| Significant event | `Значимое событие` | `SignificantEvent` | Event Processing | Событие с критичностью не ниже порога или связанное с сигналом. Хранится в истории событий дольше остальных ([ADR-028](../adr/0028-clickhouse-analytical-storage.md)) |
| Taxonomy | `Таксономия` | `Taxonomy` | Event Processing | Иерархический справочник типов событий, см. [event-taxonomy.md](event-taxonomy.md) |
| Severity | `Критичность` | `Severity` | Event Processing | Важность отдельного события: `info`, `low`, `medium`, `high`, `critical` |
| Correlation rule | `Правило корреляции` | `CorrelationRule` | Event Processing | Декларативное правило, порождающее сигнал из одного или нескольких событий: условие, окно, последовательность, порог или отсутствие события |
| Rule set | `Набор правил` | `RuleSet` | Event Processing | Версионированная совокупность активных правил тенанта, применяемая атомарно |
| Correlation key | `Ключ корреляции` | `correlation_key` | Event Processing | Ключ, по которому правило накапливает состояние (например, зона). Для более широкой области используется перераспределение; сигналы партиционируются по `grouping_key` |
| Window | `Окно` | `Window` | Event Processing | Интервал event time, в котором правило сопоставляет события |
| Watermark | `Водяной знак` | `Watermark` | Event Processing | Оценка момента event time, до которого все события считаются полученными |
| Signal | `Сигнал` | `Signal` | Event Processing | Результат срабатывания правила: признак ситуации, требующей внимания. Содержит тип инцидента, приоритет, ключ группировки и ссылки на события |
| Grouping key | `Ключ группировки` | `grouping_key` | Incident | Ключ, по которому сигналы объединяются в один открытый инцидент |
| Incident type | `Тип инцидента` | `IncidentType` | Incident | Класс ситуации (проникновение, пожар, отказ оборудования), определяющий сценарий и SLA |
| Incident | `Инцидент` | `Incident` | Incident | Ситуация, требующая реакции оператора. Центральный агрегат продукта |
| Priority | `Приоритет` | `Priority` | Incident | Срочность инцидента: `P1` (наивысший) - `P4` |
| Timeline | `Хронология` | `Timeline` | Incident | Упорядоченный журнал всего, что произошло с инцидентом |
| Resolution | `Решение инцидента` | `Resolution` | Incident | Итог работы: `confirmed` (реальная ситуация), `false_alarm`, `test`, `duplicate` |
| Escalation | `Эскалация` | `Escalation` | Response | Привлечение следующего уровня ответственных при нарушении SLA |
| Escalation policy | `Политика эскалации` | `EscalationPolicy` | Response | Набор SLA и уровней эскалации, привязанный к типу инцидента и приоритету |
| SLA | `SLA` | `Sla` | Response | Предельное время на принятие (`ack`) или решение (`resolve`) инцидента |
| Response plan | `Сценарий реагирования` | `ResponsePlan` | Response | Версионированный регламент действий в виде графа шагов. В интерфейсе - «сценарий» или SOP |
| Step | `Шаг` | `Step` | Response | Элемент сценария: инструкция, чек-лист, решение, команда, уведомление, ожидание, эскалация |
| Mandatory step | `Обязательный шаг` | `mandatory` | Response | Шаг, без завершения которого инцидент нельзя решить |
| Response run | `Запуск сценария` | `ResponseRun` | Response | Исполнение конкретной версии сценария по конкретному инциденту |
| Command | `Команда` | `Command` | Response | Запрос на воздействие на устройство через коннектор (заблокировать дверь, поставить на охрану) |
| Critical command | `Критичная команда` | `critical` | Response | Команда, требующая подтверждения вторым пользователем |
| Notification | `Уведомление` | `Notification` | Response | Сообщение получателю по каналу: в приложении, email, webhook |
| User | `Пользователь` | `User` | Identity & Access | Человек, вошедший через Keycloak |
| Role | `Роль` | `Role` | Identity & Access | Набор прав: `operator`, `supervisor`, `admin`, `integrator`, `auditor`, `manager` |
| Access scope | `Область доступа` | `AccessScope` | Identity & Access | Набор площадок и зон, в пределах которых действует роль пользователя |
| Audit record | `Запись аудита` | `AuditRecord` | Audit | Неизменяемая запись о действии субъекта над объектом, включённая в цепочку хэшей |
| Audit checkpoint | `Контрольная точка` | `AuditCheckpoint` | Audit | Периодически фиксируемый хэш вершины цепочки аудита |
| Envelope | `Конверт` | `Envelope` | Platform | Единая обёртка каждого сообщения Kafka: идентификатор, тенант, тип и версия схемы, времена, трассировка, полезная нагрузка |
| DLQ | `DLQ` | `DeadLetter` | Platform | Сообщение, которое этап не смог обработать, с указанием причины |

| Data quality | `Качество данных` | `DataQuality` | API | Отдельный признак `unknown`, `actual` или `stale`; последнее событие само по себе не подтверждает актуальность |

| State observation | `Наблюдение состояния` | `StateObservation` | Integration | Фактически полученные значения, доступность, время и курсор источника; история не выдаётся за новое наблюдение |
| Maintenance window | `Окно обслуживания` | `MaintenanceWindow` | Catalog | Разовый интервал обслуживания заданной области с явной политикой обработки и автоматическим завершением |
| Site duty | `Дежурство площадки` | `SiteDuty` | Response | Версионированное назначение пользователя ответственным за площадку; применяется к новым назначениям и уведомлениям |
| Responsibility transfer | `Передача ответственности` | `IncidentTransfer` | Incident | Явная передача инцидента с подтверждением принимающего пользователя; до подтверждения прежний ответственный сохраняется |
