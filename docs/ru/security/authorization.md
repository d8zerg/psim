# Аутентификация и авторизация

<!-- language-links -->
[English](../../security/authorization.md) | [Русский](authorization.md)
<!-- /language-links -->

[ADR-020](../adr/0020-authorization-model.md) определяет таблицу действий, [ADR-061](../adr/0061-live-access-validation.md) - актуальность прав. Таблица ролей находится в `contracts/authz/actions.json`. Администратор без роли оператора не получает право обрабатывать инциденты.

Каждый REST-сервис и административный gRPC Connector Gateway проверяет подпись, issuer, audience `psim`, сроки JWT и актуальность через фиксированный endpoint Keycloak introspection. API Gateway передаёт исходный bearer владельцу операции; владелец повторяет проверку и разрешение действия. Непроверенные заголовки ролей и областей не используются.

Отказ авторизации сохраняется в outbox владельца как `access.denied` с результатом `AUDIT_OUTCOME_DENIED`. Command Service, Response Engine и Notification Service сохраняют исходную операцию в `details.requested_action`. Audit Service принимает запись по устойчивому исходному идентификатору.

## Realm и клиенты

Конфигурация изолированного стенда находится в `deploy/local/config/keycloak/psim-realm.json`; `tools/env/keycloak_security.py` согласует существующий realm без удаления пользователей и назначений ролей. `psim-console` - публичный клиент Authorization Code + PKCE, без password grant. `psim-services` - конфиденциальный технический клиент без пользовательского входа. Конфиденциальный `psim` предназначен для introspection и хранения шести ролей; вход и выдача токенов через service account у него отключены.

В рабочем окружении каждому вызывающему сервису можно выделить отдельный конфиденциальный клиент introspection. Его client ID дополнительно включают в audience проверяемых токенов вместе с `psim`. Настройки сервиса:

```yaml
settings:
  issuer: https://identity.example/realms/psim
  jwks_url: https://identity.example/realms/psim/protocol/openid-connect/certs
  introspection_url: https://identity.example/realms/psim/protocol/openid-connect/token/introspect
  introspection_client: psim
  introspection_secret_file: /run/secrets/introspection
  jwks_ca_file: /run/trust/identity-ca.pem
```

Файл секрета имеет режим `0400`. Известный секрет локального стенда создаётся генератором тестового окружения; он используется только в изолированном realm. Для изменения issuer стенда reconciler одновременно задаёт frontend URL realm.

## Области

`psim_tenant` содержит один тенант. `psim_scopes` содержит `*`, UUID площадки/зоны либо `site:<uuid>` и `zone:<uuid>`. Wildcard действует внутри тенанта и не добавляет роль. Пустой набор не разрешает доступ к ресурсам. Коллекции фильтруются по разрешённым ресурсам; пустая коллекция допустима. Область площадки включает её зоны, область зоны не открывает всю площадку.

У консоли и технического клиента JWT содержит `psim_scope_set`, равный неизменяемому Keycloak user ID. Области пользователя и групп включаются только в ответ introspection. Сервер принимает до 10 000 областей, ответ до 1 МиБ. Смешанный JWT с ссылкой и непустым inline-набором отклоняется. Inline-формат поддерживается для ограниченных сервисных идентичностей: при изменении его утверждений нужен новый JWT.

Атрибуты `psim_tenant` и `psim_scopes` изменяет только администратор Keycloak. Пользователь не может расширить права через профиль. Права Keycloak Admin API не выдаются клиенту introspection. Каталог получателей имеет отдельные `view-users` и `view-clients`; он проверяет активность, текущие роли и области пользователя и групп при назначении ответственности и доставке уведомлений.

## Отзыв

Отключение пользователя, завершение сессии и ограничения realm проверяются через introspection. Изменение областей ссылочного набора применяется к прежнему JWT при следующей проверке; изменение тенанта или несовместимых утверждений отклоняет токен. Результат хранится до 500 мс; ошибки не продлевают ранее разрешённый доступ. Кэш ограничен 1024 токенами на шард и объединяет параллельные запросы одного токена. Сетевой дедлайн - 1 с.

WebSocket перепроверяет bearer при простое и перед очередной записью. Доверие к результату ограничено одной секундой, проверка начинается за 400 мс до её окончания. При отзыве, недоступности IdP или изменении ролей/областей соединение закрывается. В нормальных условиях отзыв обнаруживается в пределах трёх секунд с учётом сетевого дедлайна и уже начатой записи. Переаутентификация с прежними правами сохраняет подписки; изменение прав требует новых подписок и снимка. Возобновление из Kafka повторно фильтруется по текущим правам.

Административные операции над коннекторами требуют роли `admin` или `integrator` и области `*`. Восстановление требует отдельного действия `connector.recover`, роли `admin` и клиента `psim-console`. Рабочий поток коннектора использует mTLS, зарегистрированные отпечатки и отзыв сертификатов независимо от пользовательских JWT.

## Проверки

```sh
task test:authz
task authz:sanitizers
task authz:coverage
task arch:authz
```

Политика проверяется для каждого действия и всех ролей с подходящими и чужими площадками/зонами, пустой областью, чужим тенантом и истёкшим JWT. Компонентный набор обращается к реальным владельцам и публичному Gateway, изменяет ссылочный набор без выдачи JWT и проверяет отзыв открытых WSS-соединений. Каждый отказ из outbox проверяемых сервисов сверяется с исходным идентификатором и результатом в Audit Service. Проверка профиля подтверждает изменение обычного поля, скрытие защищённых атрибутов и невозможность самостоятельно сменить тенант или выдать область `*`.

Диагностика сохраняется в `build/authz/<preset>`; токены и секреты в отчёт не записываются. Ошибки санитайзеров и ненулевой код завершения сервиса отклоняют прогон. `authz:coverage` начинает измерение с пустого каталога профилей; регрессии уведомлений, 500 WSS-клиентов и сквозного потока запускаются отдельными задачами `notifications:test`, `realtime:test` и `flow:test`.
