# Дизайн-система и UX-основа

[ADR-062](../adr/0062-design-system-and-stable-updates.md) определяет общие решения. Компоненты находятся в `web/packages/design-system`, настройки и словари - в `web/apps/console/src/ui`.

## Просмотр

```sh
task web:dev
```

Консоль доступна на `http://localhost:5173/`, витрина - на `http://localhost:5173/design-system.html`. Витрина содержит демонстрационные данные и не требует запуска серверных сервисов. Рабочая лента на главной странице использует прежний API и realtime-протокол.

В шапке доступны тема, плотность, режим работы и язык. Темы: тёмная, светлая, высококонтрастная и ночная; плотности: обычная, компактная и крупная для видеостены. Режимы обычной работы, кризиса, учений и видеостены выбираются явно. По умолчанию используются тёмная тема, обычная плотность и русский язык. Все настройки применяются сразу и сохраняются; если хранилище недоступно, работают в пределах текущей страницы. Для проверки сценариев витрины нужно дождаться завершения её первичной загрузки.

При смене языка сначала загружаются его словари, затем одновременно меняются подписи и `html.lang`. Текущий экран остаётся смонтированным во время ожидания и сетевой ошибки. Повторная попытка после ошибки загрузки модуля требует явной перезагрузки; незавершённая работа автоматически не сбрасывается.

## Каталог компонентов

```sh
task web:catalogue
```

Ladle доступен на `http://localhost:61000`. Истории Actions, Forms, Status и Data показывают состояния 63 компонентов, включая недоступные действия, загрузку и ошибки. Аддон Axe включён; взаимодействия проверяет Playwright. В каталоге доступны четыре темы, три плотности, ru/en, четыре режима и расширение переводимых строк для проверки длины. Идентификаторы и введённые значения не расширяются. Режим PSIM расположен на обёртке компонентов и не изменяет режим просмотра Ladle.

Сборка проверяет наличие истории для именованных экспортов текущих компонентов. Браузерный прогон сверяет метаданные с реально отрисованными примерами и проверяет клавиатуру форм, подтверждение команды, Escape и возврат фокуса. Для каждой группы сохраняются 24 эталона по теме, плотности и языку; отдельно проверяются восемь вариантов псевдолокализации на узком окне. Axe проверяет все четыре режима в каждом сочетании представления без дополнительных файлов. Снимок всей страницы включает нижние компоненты истории.

`task web:catalogue:check` сравнивает эталоны, `task web:catalogue:visual:update` явно обновляет их для просмотра. Для отдельной проверки можно передать `GREP`, например `task web:catalogue:check 'GREP=confirmation|native form'`. Ladle собирается отдельно и не входит в бюджет и поставку рабочей консоли.

## Токены и компоненты

Цвета обозначают роль элемента. Тема меняет значения токенов, компоненты не выбирают собственную палитру.

| Группа | Токены | Назначение |
|---|---|---|
| Поверхности | `background`, `card`, `elevated`, `muted` | Фон страницы, панели, диалоги, заголовки таблиц и вторичные заливки |
| Текст | `foreground`, `muted-foreground`, `link` | Основной и вторичный текст, ссылки |
| Границы | `border`, `input`, `ring` | Разделители панелей; границы контролов и контур фокуса с контрастом не ниже 3:1 |
| Действие | `primary`, `primary-foreground` | Заливка основного действия и текст на ней |
| Статусы | `danger`, `warning`, `success`, `info` и `<tone>-solid`, `<tone>-solid-foreground` | Текст и значки статуса на любой поверхности; заливка критичных действий и маркеров |

Статус имеет три формы: текстовый цвет `<tone>`, заливку `<tone>-solid` и производный фон, смешанный с `card`. Одно значение не используется одновременно для текста и для заливки: светлый текстовый цвет тёмной темы не годится для фона кнопки. Все пары текста проходят WCAG AA 4,5:1 во всех четырёх темах. Выделенная строка таблицы использует `--selected` и левую полосу `primary`.

Для графиков выделены компонентные роли `chart-series`, `chart-axis`, `chart-grid` и `chart-selection`, связанные с семантикой темы. Обычные количественные ряды нейтральны; значения повторяются в таблице.

Приоритет P1 показывается заливкой `danger-solid`, P2-P4 - приглушённой меткой. Состояние инцидента и приоритет используют разные метки, чтобы цвет не перегружался.

Обычная плотность: контрол не ниже 40 px, строка таблицы - 48 px. Компактная: контрол - 32 px, строка - 36 px. Размеры кнопок `sm`, `md`, `lg` вычисляются от `--control-height` и сохраняют пропорции в обоих режимах. Размеры заданы CSS-переменными; высота строки может увеличиваться для содержимого. Крупная плотность использует контрол 64 px, строку 80 px и увеличенный корневой размер шрифта. На узком экране карточки переходят в одну колонку, таблица имеет собственную горизонтальную прокрутку. Поля не обрезаются вместе с доступными именами.

- `Button`: `loading` блокирует повторный запуск, сохраняя имя и размеры, включая `asChild`; варианты основного, вторичного, опасного и дополнительного действия; обычная кнопка не отправляет форму без явного `type="submit"`.
- `Field`, `SelectField`: связанная подпись, подсказка и ошибка, `aria-invalid` и `aria-describedby`; внешние `id` и `aria-describedby` сохраняются, `required` отмечается в подписи. `className` относится к обёртке поля.
- `Switch`: переключатель настройки с `role="switch"`, применяется сразу.
- `Badge`: статус с текстом и цветом; `emphasis="solid"` только для критичных маркеров.
- `Notice`: сообщение со значком и необязательным заголовком; ошибка доступна через `role="alert"`, остальные - через `role="status"`. Постоянное содержимое страницы использует `live={false}`.
- `DataRegion`: первичная загрузка, фоновое обновление, сохранённые данные и ошибка; строка статуса резервирует место по трём переведённым сообщениям с учётом переноса строк. Измерительные элементы скрыты от доступности, сообщение объявляется один раз. Вызывающая страница решает, какие действия временно недоступны.
- `Card`: раздел с заголовком нужного уровня, надзаголовком, описанием и действиями; `EmptyState` - пустой результат или отсутствие доступа.
- `ConfirmAction`: Radix Alert Dialog, фокус на отмене, Tab внутри диалога, Escape и возврат к исходной кнопке. Сводка объекта и последствий передаётся в `details`; недоступная кнопка остаётся тем же DOM-узлом.

Дополнительные точки входа:

- `@psim/design-system/controls`: Textarea, Checkbox, RadioGroup, NumberInput, Slider, IconButton, ButtonGroup, Progress, Spinner, Skeleton, DescriptionList, Stat, Timeline, Stepper, Tag, Avatar и Kbd.
- `@psim/design-system/icons`: именованные иконки и предметный набор; Icon требует подпись либо явный `decorative`, IconButton требует собственную подпись.
- `@psim/design-system/alarm-model`: независимые состояние условия, подтверждение и видимость тревоги; автомат команды с подтверждением другим пользователем и запретом повтора неизвестного исхода.

Фоновое обновление не блокирует действия: данные остаются актуальными. Действия блокируются только при устаревших данных.

## Обновления без мерцания

1. `theme-init.js` исполняется в head до модулей. Он проверяет поля сохранённых настроек и сразу задаёт тему, фон и `html.lang`; React не переключает начальную тему поздним эффектом.
2. Строки не исчезают при `isFetching` или восстановлении соединения. До успешного первого снимка показывается область загрузки; после него остаётся прежняя таблица с отдельным статусом обновления.
3. При ошибке сохранённые строки помечаются как устаревшие. Рабочие действия блокируются до получения актуальных данных; цвет online не используется для потерянного соединения.
4. React key содержит устойчивый ID. Новая версия обновляет существующий DOM-узел; состояние соединения не пересоздаёт карточки. Одинаковый снимок сохраняет объекты и массив строк.
5. Закреплённая навигация сообщает свою высоту через ResizeObserver в `scroll-padding-top`; переход к заголовку и клавиатурный фокус остаются ниже неё при смене плотности. Панели имеют постоянное место в раскладке. Ошибка выводится после сохранённого содержимого, не сдвигая текущую таблицу. Тема переключается без общей анимации фона и без мигания всей страницы.
6. Коллекции витрины используют структурное разделение TanStack Query. При подключении рабочих фильтров нельзя сохранять предыдущие данные через границы пользователя, тенанта и области доступа.

Отсутствие мерцания не означает скрывать потерю актуальности: сообщение о связи и доступность действий обновляются сразу. Новые инциденты могут добавлять строки; сохранение якоря выбранной записи в виртуализированной рабочей ленте относится к шагу 8.3.

## Оповещения и доступность

Звук выключен по умолчанию и включается отдельным контролом. Кнопки проверки позволяют прослушать короткий сигнал и увидеть текстовое оповещение. Разрешение звука браузером зависит от действия пользователя; при отказе сообщение остаётся видимым. Непрерывное мигание и автоматическое повторение звука не используются.

Состояния не передаются только цветом. У каждого поля есть подпись, у каждой таблицы - caption, у страницы - основной заголовок и ссылка пропуска навигации. Диалоги удерживают фокус и возвращают его к исходному действию. Поддерживаются reduced motion и forced colors. Длинные идентификаторы и пользовательские названия не используются как переводимые ключи.

## Проверки

```sh
task web:check
task web:e2e
task web:a11y
task web:stability
```

Визуальная регрессия и доступность проверяются отдельно:

- Витрина: 24 эталона `#foundations` по матрице тема x плотность x язык и четыре снимка шапки с выбранным режимом и проверки его CSS-эффектов. Режимы не умножают снимки неизменных компонентов.
- Каталог Ladle: 96 эталонов для четырёх групп компонентов по той же матрице и восемь снимков псевдолокализации. Всего в репозитории 132 эталона.
- Axe: полная матрица, включая режимы, сохраняется - 96 сочетаний витрины и 384 сочетания каталога. Режимы переключаются в пределах одной страницы; каждая проверка оформлена отдельным шагом теста и не создаёт снимков.
- Тесты помечены `@visual` и `@a11y`. Обновление эталонов запускает только `@visual`; `task web:check` проверяет все сценарии, включая клавиатуру и сохранение состояния.

Эти проверки входят в `task web:check` вместе с тестами смысла и бюджетами. Отдельно проверяются узкий экран, запрет localStorage, раннее применение темы с заблокированными модулями, сохранение DOM, фокуса и позиции строки при refetch, клавиатура диалога, задержка и отказ загрузки словаря. Снимки витрины сохраняются в `build/web-design-system`.


## Генерация и ограничения

Единый источник цветов - `web/packages/design-system/tokens/foundation.tokens.json`, структура [DTCG Format](https://www.designtokens.org/tr/2025.10/format/) и [DTCG Color](https://www.designtokens.org/tr/2025.10/color/). Это формат Community Group, а не заявление о соответствии стандарту W3C. Генератор формирует CSS, типы и метаданные TS, ранний `theme-init.js` и локальные подмножества шрифтов. Сгенерированное содержимое `src/gen` не хранится в Git. `task web:dev` сначала запускает генерацию.

Проверяются 1152 допустимые пары текста и поверхностей, заливок и подписей, границ и фокуса во всех темах и режимах. Основные текстовые пары высококонтрастной темы имеют контраст не ниже 7:1; остальные - не ниже 4,5:1. Ошибка контраста, цикл или отсутствующая ссылка останавливают генерацию. Исправные состояния нейтральны; цвет отклонения дублируется текстом. Проверка без различения цветов и forced colors дополняет Axe; генератор дополнительно проверяет читаемость подписей при симуляциях протанопии, дейтеранопии, тританопии и ахроматопсии. Эти симуляции не требуют различать приоритеты по оттенку: код и подпись остаются обязательными.

IBM Plex Sans и IBM Plex Mono поставляются локально в WOFF2 с латиницей и кириллицей и с лицензиями. Все четыре подмножества Sans и Mono предзагружаются до первого отображения приложения. `font-display: optional` сохраняет запасной шрифт, если загрузка не успела до первого отображения, без поздней смены метрик. Цифры таблиц и метрик табличные.

ICU MessageFormat используется для динамических форм числа; Intl-утилиты форматируют числа, абсолютное и относительное время, списки и сортировку с явным часовым поясом. Типы и проверки сопоставляют ключи ru/en. Продуктовые и демонстрационные словари разделены; загружается только выбранный язык. Соглашения о терминах и загрузке приведены в [глоссарии](ui-glossary.md).

[ADR-065](../adr/0065-ui-loading-budgets.md) задаёт суммарный бюджет 260 КБ JS gzip, прежние 150 КБ начального JS, 15 КБ CSS и 150000 байт WOFF2. Начальный бюджет учитывает статические imports и обычные script в HTML. Каждый экспортируемый компонент имеет отдельную проверку размера с внешними React/ReactDOM; отсутствие записи о новом компоненте останавливает проверку. ESLint запрещает буквальные цвета и классы палитры в приложении, дополнительная проверка запрещает отдельную шкалу в CSS приложения. Общие раскладки находятся в дизайн-системе.

Эталоны обновляются явно командой `task web:visual:update`, которая запускает только визуальные тесты, и просматриваются после генерации. Обычный `task web:check` только сравнивает снимки, не принимает изменения автоматически. Состояние требований приведено в [реестре приёмки](design-system-acceptance.md); реализация готова к утверждению. Операторские прогоны, SUS и замеры с участниками исключены.

## Сложные компоненты и API

Пакет предоставляет отдельные импорты `@psim/design-system/forms`, `/overlays`, `/navigation`, `/collections` и `/domain`. Основная точка входа сохраняет базовые компоненты. Radix управляет фокусом, Escape, возвратом к триггеру и клавиатурой диалогов, панелей, popover, tooltip и меню. `ConfirmAction` использует AlertDialog и ставит начальный фокус на отмену.

`Combobox` отменяет устаревший поиск через AbortSignal, сохраняет фокус в поле и виртуализирует варианты. Выбор периода сохраняет местное время и явный часовой пояс. `FileUpload` принимает транспорт от приложения, блокирует поздние результаты после отмены и показывает отчёт по строкам. `ValidatedForm` использует RHF/Zod, сводку ошибок и фокус на первой ошибке.

`DataTable` использует TanStack Table и Virtual: стабильный `id`, сортировка, фильтр, видимость и закрепление столбцов, выбор, групповые действия и стрелочная навигация grid. Пробел переключает выбор, Home/End меняют столбец, Ctrl+Home/Ctrl+End перемещают к границам коллекции. Вставка записей сохраняет выбор и якорь прокрутки. Дерево загружает потомков по запросу, сохраняет выбор при раскрытии и поддерживает Arrow/Home/End/Space/Enter. Масштабируемый план имеет именованные маркеры, легенду и текстовый список; график повторяет значения в таблице.

Нативные контролы передают ref и стандартные свойства соответствующему DOM-контролу; className у подписанного поля относится к его обёртке. `Button` поддерживает asChild и ref дочернего HTMLElement; без asChild ref ограничен HTMLButtonElement. Дочерний компонент должен передавать ref и события. asChild не используется для объединения нескольких интерактивных контролов. `Switch`, `Combobox`, `MultiSelect`, `RadioGroup`, `Tabs` и диалоги поддерживают управляемые value/open/checked с callback и неуправляемые defaultValue/defaultOpen/defaultChecked. Управляемый режим не меняют во время жизни компонента.

`data-state`, aria-invalid, aria-busy и aria-selected отражают состояние; источник истины определяется API компонента. TSDoc описывает ограничения отдельных контролов. Базовая геометрия и варианты находятся в CVA-рецептах с Tailwind. Функциональный CSS остаётся для нативного select, геометрии переключателя, резервирования статуса, таблиц, forced colors, reduced motion и индикатора загрузки. Приложение не дублирует эти правила.

## Оперативный симулятор

Кнопка «Открыть оперативную симуляцию» загружает тяжёлый модуль отдельно. Seed 42 и логические часы обеспечивают повторение сценария: обычный шаг, 500 тревог, разрыв, очередь, восстановление, задержка и смена. Снимки питают ленту и план; в истории и при потере связи изменяющие действия недоступны. Сводка восстановления показывает число полученных событий. Группы сохраняют количество, старейшее время, наивысший приоритет и доступ к исходным записям.

Макет показывает полную модель тревоги, отложенные и подавленные состояния с основанием, срок SLA и переназначение, присутствие и временную мягкую блокировку. Сводка смены принимается другим оператором после просмотра конкретной версии; изменение данных снимает отметку просмотра. Предпросмотр команды фиксирует объект, основание и последствия; второе подтверждение исключает автора запроса. Неизвестный исход не приводит к повторной отправке.

Звук включается явно: разные тоны P1/P2, ограничение повторов P1, громкость и проверка динамиков. Наплыв использует агрегированный сигнал и один live-регион со счётчиком не чаще раза в секунду. Таймеры времени и SLA могут обновляться отдельно от ленты. Ночная тема по расписанию и напоминание о паузе включаются оператором. Для многомониторного размещения доступны одна и две колонки панелей; видеостена использует соответствующие режим и плотность. Режим учений показывает число корректных приёмов; кризис выбирается явно.

Ассистент выполняет локальный поиск по видимым фактам и показывает идентификаторы и версии источников. Без подходящих источников он не формирует ответ. Это детерминированный макет чтения, без вызова LLM или выполнения команд. Серверная реализация, доставка команд, достоверное присутствие, синхронизация окон, видео и интеграция локального LLM относятся к отдельному серверному объёму.

## Версии и устаревание

Изменения публичного API сопровождаются changeset в `web/.changeset`. `task web:changeset:status` проверяет план версий без изменения файлов версий, коммитов, тегов и публикации. Текущий план содержит minor дизайн-системы и realtime-клиента и зависимый patch консоли. Запуск версионирования и публикации не входит в автоматическую проверку.

Устаревающий экспорт получает TSDoc `@deprecated`, замену и миграционную запись в changeset. Совместимый alias сохраняется как минимум два minor-релиза; удаление происходит только при следующем major с описанием перехода. Для экспериментального API ограничение явно записывается в его TSDoc до использования приложением.

## Воспроизводимое сравнение

`task web:benchmark` запускает отдельный worker с одинаковыми данными для невиртуального и виртуального вариантов. Протокол, результаты и ограничения приведены в [приёмке](design-system-acceptance.md#протокол-технического-сравнения). Сырые серии остаются в `build/web-benchmark/results.json`; временные показатели проверяются отдельно от основной визуальной матрицы, без параллельного браузерного набора.
