# Resource Catalog

`psim-resource-catalog` хранит локации, типы устройств, устройства, источники, версии планов и разовые окна обслуживания. [ADR-051](../adr/0051-resource-catalog.md) фиксирует границы транзакций и взаимодействие с Gateway. REST описан в [контрактах](../../contracts/proto/psim/api/v1/catalog.proto).

## Запуск и проверки

```sh
task catalog:test
task catalog:bench
task catalog:sanitizers
task catalog:coverage
```

По умолчанию задачи создают отдельный Compose-проект `psim-catalog-test`. `PROJECT` позволяет выбрать другое тестовое окружение. Проверка поднимает два экземпляра, инфраструктуру и потребителя Kafka. Созданный ею проект удаляется вместе с его тестовыми томами; в существующем окружении останавливаются только процессы проверки. Диагностика и отчёт находятся в `build/resource-catalog/<preset>/`.

Сервис поставляется отдельным Debian-пакетом и образом `psim-platform/psim-resource-catalog`. Пример локальной конфигурации: [resource-catalog.yaml](../../deploy/local/config/catalog/resource-catalog.yaml). Локальное окружение разрешает открытые соединения с тестовыми PostgreSQL, Kafka и Keycloak; REST остаётся HTTPS. Для поставки нужны защищённые соединения и секреты своего окружения. `pg_user`, `pg_database` и `pg_port` позволяют использовать отдельную роль с доступом только к схеме `catalog`; `registry_ca_file`, `registry_certificate_file` и `registry_private_key_file` задают доверие Schema Registry. Локальный каталог увеличивает предел результата SQL до 128 МиБ для страниц до 1000 устройств.

## API и права

JSON использует отображение Protobuf: lowerCamelCase, строковые имена перечислений, версии строками. Неизвестные и повторяющиеся поля отклоняются. Ошибки имеют тип `application/problem+json` и стабильный код каталога ошибок.

- `GET /v1/locations`, `/v1/device-types`, `/v1/devices`, `/v1/connectors`, `/v1/maintenance-windows` возвращают страницы с `pageSize`, `pageToken` и `nextPageToken`.
- `POST` коллекции создаёт ресурс. `Idempotency-Key` - обязательный UUID. Точный повтор возвращает исходный результат; другое содержимое с тем же ключом отклоняется.
- `PUT` ресурса заменяет его изменяемые поля; `If-Match: "N"` обязателен. Ответ содержит `ETag`. Путь и идентификатор тела должны совпадать.
- `POST /v1/locations/{id}:archive` требует пустую локацию и текущую версию.
- `GET /v1/devices` поддерживает фильтры `locationId`, `connectorId`, `deviceTypeId`, `state`. Локация включает вложенные зоны.

JWT проверяется по настроенным issuer, audience `psim` и JWKS. `psim_tenant` обязателен. `psim_scopes` - JSON-массив UUID площадок либо `*` для всего тенанта. Роль `admin` даёт запись только в этой области; роль `operator` - чтение своей площадки. Общие типы устройств доступны в области всего тенанта. Просмотр чужого ресурса в своём тенанте возвращает 403 и аудит; другого тенанта - 404.

Уровни иерархии: площадка -> здание -> этаж; зона может принадлежать этажу, зданию или площадке. `siteId` вычисляется из родителя и не меняется при переносе локации. Координаты устройства допустимы только для зоны на этаже с планом. Перенос зоны и изменение размеров плана проверяют существующие координаты. Идентификатор источника вычисляется по ADR-029 и совпадает с Gateway.

## Импорт и экспорт

`POST /v1/imports?format=json&dryRun=false` принимает JSON-массив устройств, а `format=csv` - CSV с заголовком. Предел - 100 000 строк и 64 МиБ входа. `GET /v1/imports/{id}` возвращает состояние, счётчики и ошибки с номером строки. Отчёт содержит первые 1000 ошибок; общий счётчик учитывает все ошибки.

CSV использует поля `deviceId`, `deviceTypeId`, `zoneId`, `siteId`, `connectorId`, `externalId`, `name`, `sources`, `position`, `state`, `version`. `sources` и `position` - JSON внутри CSV-ячейки. Поддерживаются кавычки, переводы строк и экранирование кавычек. Неизвестные и повторяющиеся столбцы отклоняются.

Задание и прогресс сохраняются до ответа. После перезапуска другой экземпляр продолжает с первой незафиксированной строки. Повторный импорт по `(connectorId, externalId)` обновляет прежнее устройство; `deviceId` можно опустить. Если он задан, он должен совпадать с существующей внешней идентичностью. Ошибки строки не отменяют остальные строки. `dryRun=true` сохраняет только задание и отчёт проверки.

`GET /v1/devices:export?format=json&locationId=<id>` или `format=csv` возвращает устройства разрешённой области. Экспорт ограничен 100 000 устройств и 64 МиБ JSON-данных. Пагинация и экспорт показывают актуальные данные по мере чтения; для согласованного снимка следует остановить административные изменения на время выгрузки.

## Планы этажей

`PUT /v1/locations/{id}/floor-plan?width=100&height=100` принимает бинарный PNG/JPEG и `If-Match` версии этажа. Пределы: 20 МиБ, 16 миллионов пикселей, положительные размеры в условных единицах. Метаданные содержат `fileId`, владельца, площадку, версию, размер, тип, SHA-256 и размеры в пикселях.

`GET /v1/locations/{id}/floor-plan` читает текущую версию; `?version=N` - историческую. `/floor-plan/versions` возвращает страницы метаданных. Каждый запрос заново проверяет область. Bucket не используется как публичный endpoint.

Отказ записи объекта, проверки целостности или транзакции привязки оставляет предыдущую версию доступной. Фоновая очистка проверяет непривязанные резервации каждые 10 секунд после их истечения. Предыдущие привязанные версии сохраняются. Временный каталог содержит только передаваемые байты и не является источником данных; незавершённые передачи старше часа удаляются при запуске.

## Обслуживание

`POST /v1/maintenance-windows` принимает `deviceId` либо `zoneId`, `startsAt`, обязательное `endsAt`, `reason`, `responsible`, `suppression.eventTypes` и/или `suppression.ruleIds`. Время - UTC. Политика перечисляет конкретные типы или UUID правил. Пустая политика и пожарные типы не допускаются.

Сервер назначает состояние и версию. Плановое окно становится активным, затем завершённым. `PUT` меняет незавершённое окно с `If-Match`; начало уже активного окна сохраняется. `POST /v1/maintenance-windows/{id}:cancel` завершает его явно. Завершённые и отменённые интервалы доступны для истории и не открываются заново.

Каждое изменение и автоматический переход фиксируются с аудитом. Запись аудита содержит номер версии, полный снимок объекта и идентификатор вызвавшего изменение сообщения; прежнюю политику можно восстановить после компактации потока конфигурации. Конфигурационный поток хранит и терминальные версии. Потребители сравнивают время приёма события с зафиксированным `activatedAt` и окончанием `endsAt`; при отмене окончание ограничивается `completedAt`. Окно без `activatedAt` не подавляет сигналы. Старый replay не включает обслуживание задним числом. Пожарные события и P1 проходят независимо от выбранной политики. Реализация подавления новых сигналов принадлежит Correlation Engine; каталог хранит и распространяет политику.

## Регистрации коннекторов

Каталог получает полные версии регистраций из `psim.catalog.v1`. Владельцем доверия остаётся Gateway; каталог не читает его таблицы. REST регистрации, ротации и отзыва передаёт исходный JWT через mTLS.

Для регистрации `certificatePem` передаётся параметром запроса вместе с телом `Connector`. Ротация принимает `certificatePem` в теле, отзыв - причину и необязательный `fingerprint`. Без отпечатка коннектор отключается целиком. Эти операции требуют роли `admin` или `integrator` и области `*`. Gateway проверяет сертификат и подтверждает применение изменения живыми экземплярами. При неопределённом исходе повторяется тот же `Idempotency-Key`.

Поля динамического `ConnectorStatus` заполняются владельцем проекции состояния; текущий ответ каталога содержит регистрацию. Состояние соединения не доказывает актуальность устройств.

## Требования к поставке

На одной машине сервис использует общие PostgreSQL, Kafka и закрытый S3 bucket. В кластере два экземпляра подключаются к одной базе и одному bucket; обработчики импорта, обслуживания и outbox согласуются через транзакции и блокировки PostgreSQL. Локальное содержимое временного каталога не требуется для восстановления. Для него нужен закрытый записываемый каталог с квотой, достаточной для ограниченного числа одновременных передач; остальная файловая система процесса может быть доступна только для чтения.

Конфигурация поставки должна задавать отдельную роль БД для схемы `catalog`, права S3 только на bucket планов, TLS-доверие, служебный сертификат к Gateway и защищённые файлы секретов. Внешний порт обслуживает HTTPS; runtime публикует внутренние `/health/live`, `/health/ready` и `/metrics` на административном порту. Резервная копия включает метаданные PostgreSQL и все привязанные версии объектов; при восстановлении проверяются ссылки, размеры и SHA-256. Проверка резервного копирования и чистого восстановления выполняется в шаге 9.3.
